Create an Agent that Remembers with Agent Platform Memory Bank

Imagine having a conversation with an expert financial advisor, personal trainer, or research partner. You discuss your goals, share your background, critique ideas, and lay out long-term plans. Now imagine that the next morning, you call them back—and they have no idea who you are, what you talked about, or what decisions you reached together.

LLMs are completely stateless so they do not have a built-in memory that keeps the record of the past interactions. While foundational models have grown exponentially in raw intelligence and context window capacity, raw context size does not equal memory. True intelligence requires continuity. To transition from transactional chatbots to autonomous, personalized digital colleagues, AI agents need robust, production-grade memory systems.

In this guide, we will explore Agent Platform Memory Bank—a fully managed, cognitive memory infrastructure on Google Cloud. We will cover the mechanics of agent harnesses, dive into context engineering, dissect short-term vs. long-term memory architectures, and walk through building a persistent, memory-enabled agent from scratch using Google's Agent Development Kit (ADK) and the Agents CLI (google-agents-cli).

Introduction to Agents and the Agent Harness

Before tackling memory, we must establish clear definitions for modern AI agents and the infrastructure that hosts them.

What Is an Agent?

At its core, an AI Agent is a system where a Large Language Model (LLM) is endowed with:

  • Perception: Interpreting user input and environmental state.
  • Reasoning & Planning: Decomposing complex objectives into actionable steps (e.g., ReAct, Chain-of-Thought, or Plan-and-Execute loops).
  • Tool Use (Grounding): Interacting with external APIs, databases, calculators, and enterprise software.
  • Execution & Reflection: Iterating toward an objective, observing tool execution results, and self-correcting when errors occur.

What Is an Agent Harness?

A raw LLM cannot execute shell commands, manage state across API calls, or enforce enterprise security boundaries on its own. It is simply a text-in, text-out predictive engine.

An Agent Harness (also referred to as the Agent Runtime or Execution Environment) is the software scaffolding and control plane that wraps around the agent model.

The Agent Harness is responsible for:

  1. Lifecycle Management: Instantiating agent sessions, preserving conversational turns, and handling graceful terminations.
  2. Tool Sandboxing: Resolving model function calls against executable tools, validating arguments, enforcing rate limits, and securing credentials.
  3. Guardrails & Safety: Intercepting inputs and outputs to enforce safety policies, compliance checks, and prompt-injection mitigations.
  4. Observability & Auditability: Emitting OpenTelemetry traces, latency breakdowns, token consumption metrics, and step-by-step reasoning logs to Cloud Logging and Cloud Trace.
  5. Memory Orchestration: Intercepting turns to retrieve relevant historical context before the prompt reaches the LLM, and consolidating facts asynchronously after the turn concludes.

In the Google Cloud ecosystem, the Vertex AI Agent Engine (now part of the Gemini Enterprise Agent Platform) serves as this enterprise-grade Agent Harness.

Why Agent Memory Is Crucial

A common misconception in the era of 1M+ and 2M+ token context windows is: "If our context window is virtually limitless, why do we need dedicated memory systems? Why not just pass the entire chat history into every request?"

This question leads directly to the core discipline of Context Engineering.

The Failure Modes of Naive Context Dumping

Passing unbounded conversational history directly into the context window triggers severe operational and cognitive bottlenecks:

  1. Context Rot & "Lost in the Middle": Even frontier models suffer from degraded recall and reasoning when buried under hundreds of thousands of tokens of raw conversational transcript. Crucial instructions or user preferences expressed 50 turns ago get diluted among irrelevant pleasantries and intermediate tool outputs.
  2. Quadratic Latency & Throughput Degradation: Time to First Token (TTFT) scales with prompt token length. Feeding 100,000 tokens of chat history on every turn results in latency spikes, frustrating real-time interactive users.
  3. Escalating Token Economics: Re-sending entire histories on every interaction consumes massive token volumes on both prompt caching misses and API billing.
  4. Session Boundaries: When a user closes their browser or starts a new session a week later, the in-memory context window resets completely.


Context Engineering

Context Engineering is the deliberate art and science of curating the most information-dense, high-signal, and task-relevant context for the model at each turn.

Instead of treating the context window like an unbounded hard drive, context engineering treats it like high-speed L1 CPU Cache.

  • The Context Window is the working registers and L1 cache.
  • The Session Buffer is RAM (fast, temporary, session-scoped).
  • The Memory Bank is NVMe persistent storage (durable, indexed, searchable, personalized across sessions).

Memory systems power context engineering by dynamically extracting core semantic facts, updating user profiles, discarding transient conversational scaffolding, and serving precise contextual knowledge just in time.

Memory Architectures in Google Cloud Agent Platform

Agent memories can be classified in two categories, Short-Term Memory and Long-Term Memory.

Short-Term Memory (Session Memory)

  • Scope: Bound to a single conversational session ID.
  • Contents: The immediate sliding window of user-agent turns, system prompts, intermediate thought traces, and tool execution call/response pairs.
  • Storage: Ephemeral in-memory caches, Vertex AI Agent Session Services, or fast key-value stores (e.g., Cloud Memorystore / Redis / Firestore).
  • Lifecycle: Destroyed or archived when the session expires or the user resets the conversation.

Long-Term Memory (Vertex AI Agent Engine Memory Bank)

  • Scope: Bound to an entity (typically a user_id or an enterprise account), persisting across days, months, and distinct sessions.
  • Contents: Extracted facts, entity relationships, declared preferences, past goals, and behavioral patterns.
  • Mechanism:
  1. Autonomous Fact Extraction: When a conversation concludes or periodically throughout a session, an asynchronous background pipeline powered by Gemini reviews the transcript.
  2. Memory Reconciliation: The pipeline evaluates new statements against existing memories. If a user says "I recently moved from Austin to Seattle", the system updates the previous residence fact rather than storing conflicting truths.
  3. Vector Indexing & Semantic Search: Extracted memories are embedded and stored in managed vector indexes.
  4. Scoped Isolation: Memory spaces are strictly scoped per user and tenant, ensuring GDPR/CCPA compliance and preventing multi-tenant data leaks.

4. Setting Up Memory Bank for Long-Term Memory

The Vertex AI Agent Engine Memory Bank provides fully managed long-term memory without requiring you to manually provision vector databases, write embedding extraction scripts, or design retrieval-augmented generation (RAG) pipelines for user facts.

# 1. Initialize the Long-Term Memory Service

# VertexAiMemoryBankService connects directly to the Agent Engine backend when configured

if AGENT_ENGINE_ID:

    memory_service = VertexAiMemoryBankService(

        project=PROJECT_ID,

        location=LOCATION,

        agent_engine_id=AGENT_ENGINE_ID,

    )

else:

    memory_service = InMemoryMemoryService()

async def generate_memories_callback(callback_context: CallbackContext) -> None:

    """Sends the session's events to Memory Bank for automatic memory generation."""

    try:

        await callback_context.add_session_to_memory()

    except ValueError:

        # Memory service is not attached to this runner (e.g. in basic tests)

        pass

    return None

# 2. Define the Agent Instructions and Tools

agent = Agent(

    name="concierge_agent",

    model="gemini-2.5-pro",

    instruction="""

You are an intelligent, highly personalized executive concierge assistant.

Your goal is to assist the user with recommendations, scheduling, and planning.

CRITICAL INSTRUCTIONS FOR MEMORY:

1. Always consult your recalled memories about the user to personalize your answers.

2. If the user mentions a personal preference, allergy, favorite place, or goal, acknowledge it naturally.

3. Never contradict established user memories unless the user explicitly updates them.

""",

    # The agent preloads memories into context and saves new memories after turns

    tools=[PreloadMemoryTool()],

    after_agent_callback=generate_memories_callback,

)

root_agent = agent

app = App(name="concierge_agent", root_agent=agent)

# 3. Configure the Runner (Agent Harness)

# The Runner orchestrates Session state, Long-Term Memory, and Model Invocation

runner = Runner(

    app=app,

    session_service=InMemorySessionService(),  # Short-term memory buffer

    memory_service=memory_service,  # Long-term persistent Memory Bank

)

def handle_user_message(user_id: str, session_id: str, message_text: str) -> str:

    """Process an incoming turn through the memory-augmented harness.

    Args:

        user_id: The unique identifier for the user (memory scope).

        session_id: The identifier for the current conversational session.

        message_text: The user's input prompt.

    """

    # Execute the turn through the runner.

    # The runner automatically:

    # 1. Retrieves relevant facts from Memory Bank scoped to `user_id`.

    # 2. Injects them into the system context.

    # 3. Executes the agent reasoning loop.

    # 4. Triggers background fact consolidation into the Memory Bank.

    events = runner.run(

        user_id=user_id,

        session_id=session_id,

        new_message=types.Content(

            role="user",

            parts=[types.Part.from_text(text=message_text)],

        ),

    )

    texts = []

    for event in events:

        if event.content and event.content.parts:

            for part in event.content.parts:

                if part.text:

                    texts.append(part.text)

    return "".join(texts)

import asyncio

import json

import os

import re

from collections.abc import AsyncGenerator

from pathlib import Path

from typing import Any

import agentplatform

def sanitize_session_id(session_id: str) -> str:

    """Sanitizes session_id to conform to Vertex AI Agent Engine constraints.

    Agent Engine requires session_id to contain only lowercase letters, digits,

    and hyphens, starting and ending with an alphanumeric character.

    """

    sanitized = session_id.lower().replace("_", "-")

    sanitized = re.sub(r"[^a-z0-9-]+", "-", sanitized)

    return sanitized.strip("-")

class DeployedAgentClient:

    """Client for interacting with an agent deployed to Vertex AI Agent Runtime."""

    def __init__(

        self,

        remote_agent_runtime_id: str | None = None,

        location: str | None = None,

        metadata_path: str = "deployment_metadata.json",

    ):

        if not remote_agent_runtime_id:

            metadata_file = Path(metadata_path)

            if not metadata_file.exists():

                raise FileNotFoundError(

                    f"Deployment metadata file not found at {metadata_path}. "

                    "Please specify remote_agent_runtime_id explicitly."

                )

            with open(metadata_file) as f:

                metadata = json.load(f)

            remote_agent_runtime_id = metadata["remote_agent_runtime_id"]

        self.remote_agent_runtime_id = remote_agent_runtime_id

        if not location:

            # Parse location from resource name:

            # projects/{project}/locations/{location}/reasoningEngines/{engine_id}

            parts = remote_agent_runtime_id.split("/")

            if len(parts) >= 4 and parts[2] == "locations":

                location = parts[3]

            else:

                location = os.getenv("GOOGLE_CLOUD_LOCATION", "us-central1")

        self.location = location

        self.platform_client = agentplatform.Client(location=self.location)

        self.agent = self.platform_client.agent_engines.get(

            name=self.remote_agent_runtime_id

        )

    async def stream_query(

        self,

        message: str,

        user_id: str,

        session_id: str | None = None,

    ) -> AsyncGenerator[dict[str, Any], None]:

        """Streams events from the deployed agent."""

        valid_session_id = sanitize_session_id(session_id) if session_id else None

        async for event in self.agent.async_stream_query(

            message=message,

            user_id=user_id,

            session_id=valid_session_id,

        ):

            yield event

    async def query(

        self,

        message: str,

        user_id: str,

        session_id: str | None = None,

    ) -> str:

        """Sends a query to the agent and returns the accumulated text response."""

        full_text: list[str] = []

        async for event in self.stream_query(

            message=message,

            user_id=user_id,

            session_id=session_id,

        ):

            if isinstance(event, dict) and event.get("errorCode"):

                raise RuntimeError(f"Error from agent: {event.get('errorMessage')}")

            content = event.get("content", {})

            parts = content.get("parts", [])

            for part in parts:

                text = part.get("text")

                if text:

                    full_text.append(text)

        return "".join(full_text)

    async def add_session_to_memory(

        self,

        user_id: str,

        session_id: str,

    ) -> None:

        """Consolidates events from the specified session into the Vertex AI Memory Bank."""

        valid_session_id = sanitize_session_id(session_id)

        session = await self.agent.async_get_session(

            user_id=user_id,

            session_id=valid_session_id,

        )

        if not session:

            raise ValueError(f"Session {session_id} not found for user {user_id}")

        await self.agent.async_add_session_to_memory(session=session)

    async def search_memory(

        self,

        user_id: str,

        query: str = "*",

    ) -> list[str]:

        """Searches persistent Memory Bank for extracted facts/memories."""

        response = await self.agent.async_search_memory(user_id=user_id, query=query)

        memories = response.get("memories", [])

        facts = []

        for m in memories:

            content = m.get("content", {})

            for part in content.get("parts", []):

                text = part.get("text")

                if text:

                    facts.append(text)

        return facts

async def main():

    parser = argparse.ArgumentParser(description="Call deployed Agent Runtime agent.")

    parser.add_argument(

        "--user-id",

        default="alice_99",

        help="User ID for the session context",

    )

    parser.add_argument(

        "--session-id",

        default="sess_001",

        help="Session ID for the conversation",

    )

    parser.add_argument(

        "--message",

        default=(

            "Hi, I'm Alice. I'm training for the Boston Marathon this spring, \n"

            "      and I adhere to a strict gluten-free pescatarian diet."

        ),

        help="User message to send to the agent",

    )

    parser.add_argument(

        "--record-to-memory",

        action="store_true",

        default=True,

        help="Trigger Memory Bank extraction for this session after the turn",

    )

    parser.add_argument(

        "--search-memory",

        action="store_true",

        help="Search and print memories for the user instead of querying",

    )

    args = parser.parse_args()

    client = DeployedAgentClient()

    if args.search_memory:

        print(f"Searching Memory Bank for user {args.user_id}...")

        facts = await client.search_memory(user_id=args.user_id)

        if not facts:

            print("No memories found.")

        else:

            print("Recorded memories in Memory Bank:")

            for fact in facts:

                print(f"  • {fact}")

        return

    print("Initializing client...")

    print(f"Connected to agent: {client.remote_agent_runtime_id}")

    print(f"Location: {client.location}")

    print(f"User ID: {args.user_id}")

    print(f"Session ID: {args.session_id}")

    print(f"Message: {args.message.strip()}\n")

    print("--- Streaming Agent Response ---")

    async for event in client.stream_query(

        message=args.message,

        user_id=args.user_id,

        session_id=args.session_id,

    ):

        if isinstance(event, dict) and event.get("errorCode"):

            print(f"\n[Error]: {event.get('errorMessage')}")

            continue

        content = event.get("content", {})

        parts = content.get("parts", [])

        for part in parts:

            text = part.get("text")

            if text:

                print(text, end="", flush=True)

    print("\n\n--- End of Response ---")

    if args.record_to_memory:

        print("\nTriggering Memory Bank consolidation...")

        await client.add_session_to_memory(

            user_id=args.user_id, session_id=args.session_id

        )

        print("Memory extraction request submitted successfully.")

if __name__ == "__main__":

    asyncio.run(main())

Conclusion

As AI agents evolve from novelty demonstrations to mission-critical enterprise workflows, the systems we build around them must mature accordingly.

Relying solely on expanding context windows is a costly, high-latency trap. True agentic intelligence requires Context Engineering powered by a dual-tier memory model:

  • Short-Term Session Memory for conversational agility and multi-step reasoning scratchpads.
  • Long-Term Memory Bank for cross-session continuity, personalization, and evolving knowledge retention.

With Google Agent Engine Memory Bank, developers gain access to an enterprise-grade, fully managed memory infrastructure that seamlessly extracts, consolidates, indexes, and surfaces relevant knowledge without the burden of building custom vector databases or complex ETL pipelines. Paired with the Agents CLI (google-agents-cli) and the Agent Development Kit (ADK), creating an agent that truly remembers is no longer a multi-month engineering endeavor—it is a standard, repeatable architecture.
